    About this page
    
  
    
    
    
      
    How it runs
    
      
    The page runs the j2prompt-lint %J2PL_VERSION% wheel on CPython %PYODIDE_PYTHON% compiled to WebAssembly (Pyodide %PYODIDE_VERSION%), inside a Web Worker. Each lint calls the CLI's own main() on an in-memory file; the diagnostics are rendered from its JSON envelope. The wheel's sha256 is checked before it is installed.
    
      
    No model is called and no server does any work: every file this page loads is static and served from this site. Its Content-Security-Policy (connect-src 'self') lets the analysis contact no other host.
    
    
    
    
    
      
    PINJ scope
    
      
    PINJ flags template positions where untrusted variables reach instruction contexts — an over-approximation of prompt-injection enabling patterns — and certifies neither the presence nor the absence of an exploitable attack.
    
      
    The selected source model decides which variables are untrusted. The default is configured, using explicit sources and annotations. If no variable is marked untrusted, PINJ reports that no untrusted flow was checked. This differs from a sourceful analysis with no findings.
    
    
    
    
    
      
    What this tool does not claim
    
      
      
        
    • It does not originate static prompt linting: PromptSet introduced the concept on prompt strings in Python code. This tool works on Jinja2 templates, at the level of the template AST.
      • 
        
    • LLM judging predates this tool in PromptDoctor and Microsoft Chat Customizations Evaluations. PromptDoctor additionally executes attacks and performs LLM-based repair.
      • 
        
    • PINJ is not a prompt-injection defence; it detects no attack at inference time (see its scope above).
      • 
        
    • Its five rule classes are not a complete taxonomy of prompt defects; they are aligned to the taxonomy of Tian et al.
      • 
        
    • It does not detect semantic defects such as contradiction, ambiguity or gaps in intent coverage.
      • 
        
    • It does not originate Jinja2 variable-contract checking or framework message validation. Existing tools include promptkit-core and promptflow.
      • 
        
    • Render-free Jinja2-AST security auditing predates it in c4nary, glyphhound and chatpin. c4nary also propagates taint to identify template-planted instructions. PINJ assumes a trusted template and asks about untrusted values.
      • 
        
    • Region-aware prompt-injection taint in host code predates it in CodeQL. TaintP2X and agentic-guard also analyze host code.
      • 
        
    • Chat-format conformance checking predates it, including ChatLint's rendered conversations and gguf-template-doctor's scanner. PCHAT checks bounded conditions on the Jinja2 AST.
